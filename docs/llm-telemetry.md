# 模型调用遥测

项目会为真实模型调用记录不含业务正文的结构化事件，用于回答三个最基本的运行问题：调用是否成功、耗时是否异常、流式回答多久开始显示。

## 记录范围

每条事件只包含：

- UTC 时间、调用场景、模型提供方和模型名；
- `success`、`failure` 或 `cancelled` 结果；
- 总耗时，以及流式站内问答的首个最终答案片段时间（TTFT）；
- `timeout`、`upstream`、`configuration`、`application` 或 `internal` 失败类别。

TTFT 指浏览器可以看到的第一个最终答案片段，不是提供方发出的第一个原始 token。若最终答案过滤器必须等完整内容结束后才能安全确认正文，TTFT 会接近总耗时，这是对当前真实交互体验的反映。

事件不会记录 Prompt、模型回答、用户 ID 或上游错误正文。日志使用 `llm_telemetry` 前缀和 JSON 载荷，后续可以由日志平台采集。

## 管理员聚合接口

`GET /ai/telemetry`（也可使用 `/api/ai/telemetry`）仅允许 `admin` 角色访问，返回最近 200 次调用的：

- 请求量、成功数、失败数、取消数和成功率；
- 平均耗时与 P95 耗时；
- 流式请求的 TTFT 样本数、平均值和 P95；
- 各调用场景的数量与失败类型分布；
- 数据最小化声明和最近事件时间。

示例：

```powershell
curl.exe http://localhost:8000/ai/telemetry `
  -H "Authorization: Bearer <admin-token>"
```

普通用户会收到 HTTP 403，未登录请求会收到 HTTP 401。

## 适用边界

聚合窗口保存在单个应用进程内，最多保留 200 条，容器或进程重启后清空。它适合本地作品演示、问题定位和面试讲解，不等同于生产监控。

公开部署时仍应将结构化日志发送到持久化监控平台，按实例聚合指标，并为错误率、P95 延迟、容量和成本设置告警与负责人。当前提供方未返回稳定的 token 用量，所以项目不伪造 token 或费用数字。
