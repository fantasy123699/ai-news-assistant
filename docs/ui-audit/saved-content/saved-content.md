# 收藏与历史记录模块审查

审查日期：2026-09-11

范围：收藏列表、浏览历史、单条移除、全部清空，以及加载、空、失败和未登录状态

目标：不改变现有路由、接口、数据结构和应用外壳，让用户能够安全地找回、打开和管理个人阅读记录。

**CONDITIONAL GO** — 本模块适合作为本地作品集演示；在没有公开部署配置、恢复演练和更强会话保护证据前，不建议宣称整个项目已达到无限制公网生产标准。

## 优化前的主要风险

- 列表请求没有加载、失败或重试状态，异常会直接中断交互。
- 空状态和未登录状态只显示一句文字，没有清晰的下一步操作。
- “清空”点击后立即执行，不符合不可恢复操作的确认要求。
- 单条移除和清空依赖浏览器弹窗或没有成功/失败反馈。
- 收藏与历史条目直接拼接服务端文本，存在客户端内容注入风险。
- 条目缺少明确的键盘打开控件，记录数量和保存时间不可见。

## 已完成改进

- 统一收藏与历史的加载逻辑，并提供骨架加载、失败重试、未登录引导和可行动的空状态。
- 在标题区显示记录数量；条目补充收藏/浏览时间、分类和浏览量。
- 所有服务端文本进入 HTML 前统一转义，文章标题使用原生按钮打开。
- 单条移除增加忙碌状态、内联成功/错误反馈，避免重复点击。
- 全部清空改成页面内两步确认，支持取消并把焦点返回触发按钮。
- 空列表时禁用清空操作；列表用 `aria-busy`、状态区用 `aria-live` 传达变化。
- 保留既有视觉令牌、布局、API 和数据结构，没有引入框架或新依赖。

## 核心流程健康度

1. **进入收藏，健康：** 显示加载状态，随后呈现数量和列表；当前空列表提供“浏览新闻”入口，清空按钮禁用。
2. **进入历史，健康：** 当前账号的 2 条记录完整显示，包含分类、浏览量和浏览时间。
3. **打开记录，健康（源码与语义验证）：** 每条标题是可聚焦原生按钮，并复用现有新闻详情流程。
4. **移除单条记录，健康（安全边界验证）：** 请求期间按钮禁用，完成和失败都有内联反馈；浏览器验证未删除用户现有数据。
5. **清空全部，健康：** 第一次点击只展开风险说明；取消后 2 条记录仍保留，焦点返回“清空全部”。
6. **未登录与错误恢复，健康（源码验证）：** 提供登录或重新加载入口，不再留下空白页面或未处理异常。
7. **一般状态，健康：** 桌面视口无页面级横向溢出，交互目标沿用 44 px 基线，容器健康且 JavaScript/Python 回归通过。

## 证据与限制

- 在 Codex 内置浏览器中对同一桌面视口进行了优化前后对照，并实时检查 DOM、可访问名称、确认展开、取消、焦点恢复和记录保留。
- 为避免更改当前账号数据，未在浏览器中执行最终清空或单条删除；接口授权与删除实现通过源码审查，完整后端回归测试保持通过。
- 本轮未取得生产域名、HTTPS、备份恢复、监控告警或公网会话配置证据，因此这些项目均未标记为已验证。
