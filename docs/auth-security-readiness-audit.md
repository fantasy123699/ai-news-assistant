# 登录与会话模块就绪审查

## 结论

**CONDITIONAL GO**：适合本地作品演示和受控测试，不建议直接作为公网认证方案。置信度为 **Medium**，核心代码、迁移、单元测试和本地容器流程可以验证，但 HTTPS、Cookie 会话、生产 Redis 可用性与安全告警不在本地环境中。

## 范围与不变量

- 目标：限制同一账号与客户端来源的连续暴力尝试，并避免数据库泄露时直接暴露可用会话令牌。
- 核心流程：失败登录累计并临时锁定；成功登录返回原始令牌、数据库保存摘要；退出和认证只使用摘要；改密撤销全部会话。
- 不变量：不存在账号和真实账号使用相同错误文案与限流路径；原始令牌不得进入数据库或日志；密码更新和会话撤销必须同一事务完成。

## 上线前完成标准

公网发布前，应在 HTTPS 环境迁移到 `Secure`、`HttpOnly`、`SameSite` Cookie，验证 CSRF 防护，并让生产 Redis 不可用和高频 429 都能触发有负责人的告警。还应对跨账号攻击、代理 IP 策略、时序枚举和会话恢复执行专项安全测试。
