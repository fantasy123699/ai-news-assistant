# 登录限流与会话安全

## 登录失败限制

登录接口按“标准化用户名 + 直接客户端 IP”的 SHA-256 摘要在 Redis 中记录连续失败，不保存原始用户名或 IP。这样单个来源无法让其他来源的正常用户一起被锁定。默认规则为：

| 配置 | 默认值 | 说明 |
| --- | ---: | --- |
| `AUTH_LOGIN_MAX_FAILURES` | 5 | 触发临时锁定的连续失败次数 |
| `AUTH_LOGIN_WINDOW_SECONDS` | 300 | 失败计数的滑动有效期 |
| `AUTH_LOGIN_LOCKOUT_SECONDS` | 900 | 锁定时间 |

达到阈值时接口返回 HTTP 429 和 `Retry-After`，浏览器显示“登录尝试次数过多，请稍后再试”。登录成功会清除该账号的失败计数和锁定状态。

如果 Redis 暂时不可用，限流器会记录不含账号信息的警告并允许登录流程继续，避免缓存故障造成所有用户无法登录。公网部署应监控 Redis，因为此降级模式会暂时失去暴力破解保护。

## 会话令牌

- 登录时使用 256 位随机令牌，只把原始值返回给浏览器。
- MySQL 仅保存令牌的 SHA-256 摘要；认证和退出时同样先计算摘要再查询或删除。
- 用户修改密码时，密码更新和该用户全部会话删除在同一个数据库事务中完成，之后需要重新登录。

已有数据库必须先运行 `database/migrations/003_hash_user_tokens.sql`。迁移会将 `CHAR(32)` 扩为 `CHAR(64)` 并原地摘要已有令牌，因此当前浏览器会话无需强制退出。

## 边界

当前原生前端仍将原始令牌保存在 `localStorage`，适合本地作品演示，但不是公网最优方案。公网发布应改用 `Secure`、`HttpOnly`、`SameSite` Cookie，并补充 CSRF 防护、集中式安全事件告警和经过验证的会话恢复流程。
